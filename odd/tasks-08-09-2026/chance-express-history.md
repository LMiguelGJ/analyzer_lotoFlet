# Chance Express Dated Historical Downloader

## Objective
Create a root-level downloader that queries Loteka's official date endpoint and writes dated records containing all five ordered positions.

## Problem and rationale
`lagacy_loto/loteka_numbers.json` is a flattened one-number-per-draw history. `lagacy_loto/scrapy.py` extracts only the first prize position and has no draw date/time/contest ID. Analysis and the parity simulator need complete, timestamped draw records. The official endpoint is `https://loteka.com.do/wp-content/themes/loteka/getChanceExpress.php?fechaSeleccionada=DD/MM/YYYY`; the official page wraps draws in `#result-chanceexpress`, while the PHP endpoint can return the inner `<li>` fragment directly. Each item carries time, draw ID and five `.numero` values. Probes returned empty responses for several older dates, so the script must record empty days and report its requested date coverage without claiming all-time completeness.

## Scope
- Add one root-level Python script using existing Python dependencies (`requests`, `beautifulsoup4`).
- Query Loteka's official per-date endpoint from a configurable start date through end date; default start is the legacy script's 2019-10-15 baseline.
- Parse each official `<li>` for draw ID, requested date, local time, and all five displayed number positions in order.
- Preserve duplicate values across positions; validate five values in range 00-99.
- Store results as `metadata` plus `sorteos_por_fecha`, whose date keys map to chronological lists of `{numero_sorteo, hora, numeros}` records; each five-value array preserves official position order and zero padding.
- Include source URL in each record and report requested range, date gaps, total records, and observed coverage in metadata.
- Track requested dates with no results, report date coverage and earliest/latest records, and fail on structural parse errors rather than silently saving a falsely complete archive.
- Support output path, date-range options, and bounded-day option for safe smoke checks; scan newest dates first so recent data appears in progress immediately, while serializing date keys chronologically.
- Print the requested range, current date, per-date draw IDs/numbers, aggregate dates-with-results/empty/record counts, elapsed time and ETA; render a small Chance Express banner per date.
- Persist each completed date and its resume state in the root JSON itself; do not create a separate checkpoint file. Rerunning the same command resumes the next unprocessed date. Never modify legacy `.env` or JSON.
- Retry transient DNS/connectivity/timeout/server errors indefinitely with capped backoff, keeping the failed date pending; permanent HTTP/source-structure errors still fail visibly and preserve the in-JSON resume state.

## Constraints / non-goals
- Do not alter legacy files or the existing JSON.
- Do not fabricate missing historical results or claim all-time completeness when official endpoint dates return empty.
- Do not mix regular ChanceExpress and Extra hourly draws.
- Do not infer unique numbers per draw; repeats were observed across positions.
- No bets, account access, commits, or dependency installation.

## Acceptance criteria
- Script is in repository root, has CLI help, output path, date-range options and bounded-day option; each completed date and resume cursor are saved atomically in the root JSON, with no sidecar checkpoint.
- JSON has a `sorteos_por_fecha` object keyed by ISO date; each value is the chronological array of the date's draws, containing draw ID, local time, five ordered two-character number strings, and official source URL.
- Repeated numbers are retained; malformed cards are surfaced.
- Bounded smoke run produces parseable JSON and reports requested date coverage and empty days; scan is recent-first with chronological JSON output and visible counters/ETA; every draw is printed; same-day identical duplicate rows are deduplicated; transient network failures retry with backoff; interruptions preserve a valid JSON snapshot/resume cursor without another file.
- No tracked legacy files are changed; no commit is created.
