# LW17 phase 2 — bounded live observations

## Authority, provenance and method

This is a **measurement report, not an SLA or LW16 acceptance**. The parent diagnosed the phase-1 OneDrive failure without a product change: adapter **17/17** twice (6.89/6.85 s), full backend **166/166** (66.48 s, two known deprecations) with OS-temp basetemp. Those are **parent-run results**, not writer reruns; the original OneDrive `WinError 5` is unexplained. The writer's phase-1 frontend was 251/251. LW16 remains manual acceptance pending.

The fixed protocol was written to `phase2-protocol.md` **before** starting live measurement. Real frozen data, factory FastAPI and compiled static frontend (`serve_frontend=True`, no Vite dev server), real isolated worker and fresh DB/cache per process were used. Runtime was confined to the parent-authorized non-OneDrive OS-temp root's new `live/` child; reports/scripts are here and Chrome session artifacts under `.playwright-cli/`. No product/test/spec/tracker/README/oracle writes, installation, Ctrl+C, default-browser, UNC or signals experiment. An owned stop marker triggered `uvicorn.Server.should_exit`, followed by verified zero exit for every owned server; browser sessions were closed via named Playwright CLI `close`. Runtime and reports are **retained** for independent review.

`live-before.json`/`live-after.json`, `ui-resume-4-before.json`/`ui-resume-4-after.json`, `resource-probe-before.json`/`resource-probe-after.json`: each compares the same **106 selected source/test/config/lock/frozen-input paths**, **zero differences** (`*-integrity.json`). History JSON first/last: **2025-03-05 05:05 / 2026-09-25 18:20**, 105,426 draws. Reference fixture ranking first/last: **2025-09-02 05:10 / 2026-09-25 18:20**, 141 cases / 417 fixture sessions; these bounds are different concepts. Direct data facts are in `live-dates.json`, not copied from an old tracker summary. The oracle was not regenerated or swept across every possible start.

**Definitions.** Three cold samples are separate new processes + fresh DB/cache (`cold-1..3`), from parent `perf_counter_ns` immediately before `Popen` to first HTTP 200 `GET /api/v1/settings` after lifespan/listen. HTTP timings are same-clock request/response wall durations (network loopback, serialization included), sequential warm calls; status, bytes and queue before/after are retained per sample. UI timings use Chrome `performance.now()` on captured Enter `keydown` to the next animation frame after the destination `h1` is visible and verified; page data fetch completion is **not** included, nor CLI command overhead. p50 is median; p95 is sorted nearest-rank `ceil(.95*n)`. n=3/10 is too small for capacity or tail-latency promises. `observed_active` requires a real non-null `active_id` on both sides of a sample; no sleep was used to stretch the worker (only bounded readiness/terminal polling).

**Live cancellation:** in the verified ten-sample UI comparison, an active ID was present at all UI sample boundaries; the later detail showed run 0 running and four pending. The request to `/api/v1/queue/{id}/cancel` returned 200 in **7.104 ms** (request latency, **not terminal cancellation latency**). After graceful shutdown, a read-only SQLite observation (`cancel-persisted.json`) found experiment `cancelled`, run 0 `cancelled` without result and runs 1–4 `not_run` without results. No configuration had completed before cancellation, so **retention of completed results in this live scenario is inconclusive**; deterministic contract tests cover that separately. There was no disk-exhaustion injection; lack-of-disk behavior remains test-only.

## Integrity and limitations

The installed `playwright-cli run-code` rejected documented `--filename`, so the original UI attempt had **n=0** (`browser-ui.json`). An inline `.cmd` transport then returned a SyntaxError; a base64 transport reached the browser but missed the CLI sandbox `URL` global, and a UTF-8/Latin-1 locator mismatch produced **10 failed locator attempts**. These are retained as `ui-resume*` artifacts, **not counted as successful samples**. Final `ui-resume-4` used an ASCII CSS locator and yielded all 10 verified samples; its server start is **not** included among the original three cold measurements. Earlier extra isolated workloads were bounded to the same maximum and their failures remain reviewable, rather than erased or blended into the final distribution.

UI measures heading render, not full asynchronous data availability or input responsiveness under prolonged heavy compute. Worker load is bounded to 500 bets per strategy; no SLA, sustained concurrency, failure injection, full-history scalability, or LW16 manual acceptance is inferred. All observed owned server exits and final browser close succeeded; runtime data is deliberately retained pending the parent's decision.
